# Delivery checklist

Use on the finished `08-final-delivery/` folder.

## Approval
- [ ] Every file has passed quality review
- [ ] The client has approved the final versions (date recorded in `brand-context.md`)

## Completeness
- [ ] Every deliverable in the brief has been through quality review, strategy and other documents included
- [ ] Every deliverable in the brief is present
- [ ] Every required language version is present
- [ ] Every required format is present (see `.claude/rules/file-delivery.md`)

## Organisation
- [ ] Folder structure follows the delivery standard
- [ ] File names follow the naming convention; marked `final` only if the client approved, otherwise versioned and the package marked HELD with its release conditions
- [ ] No drafts, rejected options, duplicates or system files (`.DS_Store`, `Thumbs.db`)

## Logo package
- [ ] SVG, PDF and PNG (1x, 2x, 4x) for each lockup
- [ ] Full colour, black and white versions
- [ ] RGB and CMYK versions clearly separated

## Sources
- [ ] Editable source files included as self-contained folders (`scripts/collect_html.py`), and each opens correctly from a copy outside the repo
- [ ] Fonts included where the licence permits; otherwise listed with where to obtain them
- [ ] Image and font licences documented

## Handover
- [ ] `README.md` explains the package in plain language, in the client's primary language first, and lists every hold and every omitted deliverable
- [ ] Documents in the package refer only to the package's own folders
- [ ] Guidelines PDF included
- [ ] Files open correctly from a fresh copy of the folder
- [ ] `brand-context.md` updated with delivery date and contents
