# Security

## Summary

- The interface (JavaScript) holds no keys, has no file-system access and cannot run programs.
- It can do exactly two things: call `rpc` with a command name from a fixed list, and read media files
  the core allows.
- Keys live in the Windows Credential Manager and are used only by Rust.

## Tauri capabilities (least privilege)

`src-tauri/capabilities/default.json` grants the main window only:
`core:event:allow-listen`, `core:event:allow-unlisten` (file drop), `dialog:allow-open`, `dialog:allow-save`.
No `fs`, `shell`, `http`, `process` or `opener` plugin is installed.

Content Security Policy: scripts and styles from the app only; no remote content; media from the app's own
`studio` scheme.

## Command allow-list

`crates/core/src/rpc.rs` has one `match` with every command the app supports. A name that is not in it
returns `unknown_command`. Arguments are validated there (types, length limits, enumerations).
Settings are a second allow-list (`SETTING_KEYS`); `gpu_api_base` cannot be set from the interface.

## System commands

The app starts three programs, with fixed names and argument lists (never a shell string):

| Program | When | Arguments |
|---|---|---|
| `ffmpeg` | thumbnails, verification, export | built by the app from validated numbers and paths |
| `ffprobe` | reading media metadata | fixed, plus one file path |
| `explorer.exe` | "Open folder" | one folder, only if it is inside the library |

No user text is ever part of a program name or interpreted by a shell.

## Files

- **Path traversal:** every path built from data goes through `paths::safe_join`, which refuses `..`,
  absolute paths and drive prefixes. Project folder names are generated by the app (`slug`), with Windows
  reserved names handled.
- **Reading:** the `studio://` scheme serves a file only if it is inside the library (and is not the
  database), or is the registered original of a media-library item. Everything else gets 403.
- **Imports are checked by content, not by name:** media by magic bytes and by `ffprobe`; LoRA files must be
  valid `.safetensors` (header parsed); pickle formats (`.ckpt`, `.pt`) are refused because they can run code.
- **Project archives:** entries are checked against zip-slip; the bytes actually written are counted against
  a size limit (not the sizes the archive declares); a failed import removes what it wrote.
- **Originals:** the media library never moves, edits or deletes the user's files.
- **Deleting:** projects and LoRA files are moved to `Backups/Deleted`, not erased.

## Secrets

- Stored with `keyring` in the Windows Credential Manager under the service name "Cinematic Studio".
- Accepted names: `comfy_token`, `gpu_api_key`. There is no command that reads a secret back.
- Not written to SQLite, `project.json`, backups, exports or logs. Error messages pass through
  `secrets::redact` before reaching the interface.
- Tested: after storing a key, the database file and the status response do not contain it.

## Network

- ComfyUI address: `https://` is required; `http://` is accepted only for `localhost`/`127.0.0.1`.
  Addresses with embedded credentials or a query string are refused.
- The ComfyUI token is sent as `Authorization: Bearer` on HTTP and on the WebSocket.
- **Links received from the GPU are not followed.** The app never opens a URL returned by the server. It
  takes the file name from `/history`, refuses names with path separators or `..`, builds the `/view` URL
  itself on the configured host, limits the download to 4 GB, writes to a `.part` file, and accepts the
  file only after it decodes.
- GPU provider calls go to `https://api.runpod.io` only.
- ComfyUI must not be exposed publicly without authentication and TLS; see ARCHITECTURE.md.

## Database and user data

- The database is in the user's own Documents folder, protected by the Windows account's file permissions.
  It is not encrypted; it contains no keys.
- The installer is per user (no administrator rights) and the uninstaller does not touch the library.
- One running copy only (`tauri-plugin-single-instance`).

## Development bridge

`dev-bridge` is a development and test tool, not shipped. It listens on 127.0.0.1 only, accepts only its
own `Host`, a same-site `Origin` and JSON bodies (against CSRF and DNS rebinding), and keeps secrets in
memory.

## Known limits

- The installer is not code-signed yet; Windows SmartScreen will warn. A signing certificate is the owner's decision.
- The bundled FFmpeg is a third-party build fetched at build time from one pinned release and checked
  against a SHA-256 stored in the workflow. It is still someone else's binary; a copy the owner hosts and
  has vetted would be stronger.
- Automatic updates are not enabled.
